# Ward — Issue Index

Every GitHub issue in `dseelinger/ward`, open and closed, newest first. A checked box is a
closed issue. 131 issues in total: 105 open, 26 closed. (`#117` and `#131` are absent from
the issue list — they are pull requests or were deleted.)

- [ ] **#133 Type into the panel in the headset** — The VR settings page renders text boxes that cannot actually be filled while wearing the headset, so the desktop window is more capable than VR in violation of decision D4. Three input approaches were built and withdrawn; the issue closes either by making headset text entry work or by rewriting D4 to say settings are desktop-only and not drawing the page in VR.
- [ ] **#132 Switch the panel between curved and flat** — The panel is bent ~0.15 around the Commander, which suits a wide panel at arm's length but not everything else. The `panel curve` setting already exists; what is missing is a way to change it without taking the headset off.
- [x] **#130 Run mutants against the pure tier, and work the survivors** — Coverage floors only prove a line executed, not that anything asserted on it. `cargo-mutants` was introduced over the pure tier to find lines no test would notice changing, and the surviving mutants worked through.
- [x] **#129 The release build does not link** — The static-C-runtime release build failed at link with fifteen `__imp_` unresolved symbols from whisper/ggml objects, blocking any release. The two halves of the build disagreed about which C runtime they targeted.
- [x] **#128 Prove the anti-invention rules reach every turn** — The system prompt's "never state a fact you were not given" rules are what stop Ward speaking a wrong jump range with total confidence. This added proof that those static, cached rules actually reach every turn rather than being assumed to.
- [ ] **#127 Move transcription off the CPU** — CPU transcription costs about 2.4 seconds of every turn and is now the largest remaining chunk of latency between key release and Ward speaking. A CUDA build would be far faster but drags in the CUDA toolkit for everyone building from source, so it is deliberately not started without a decision.
- [ ] **#126 Offer an update, and install it on the way out** — There is no update code at all, so a Commander who installed by hand will never learn a new version exists. Releases would act as the update server, behind a single network gate, with "could not check" kept distinct from "up to date".
- [x] **#125 Gate a release on installing, launching and surviving** — Lint, compile and fast tests ran on every change but nothing tested the path that actually ships. Added a gate that installs the binary silently, launches it, asserts it is still alive, and synthetically tests that an upgrade preserves the data folder.
- [x] **#124 Stop a test reaching a live service** — Nothing stopped a fast-tier test opening a socket to a live provider and spending money unattended. Sockets from the first two tiers now fail loudly, audio playback is stubbed, and ambient mock-mode variables are cleared.
- [x] **#123 Mark the test tiers, and measure each one** — Five test tiers existed by decision but not in the repository — only an `ignore` attribute lumping hardware, headset and game together. Every test is now tagged pure/integration/hardware/headset/game, runnable per tier, with a coverage floor per tier instead of one global percentage.
- [x] **#122 Publish the documentation, and keep internal pages out of it** — Per-capability pages existed under `docs/` but nothing published them, so only someone already reading the source could find them. Publishing was added along with a rebuilt nav checker that loads the real build configuration and refuses escape hatches that leave pages built but unlisted.
- [x] **#121 Keep the typed path from rotting** — Typed input is the fallback when the microphone, speech model, key or environment fails, so it is used exactly when something else is already broken. It was only exercised incidentally by engine tests; this added something holding it open deliberately.
- [x] **#120 Keep working when the window is minimized** — The whole turn ran inside `eframe::App::ui`, so minimizing the window meant speech was heard and transcribed but nothing consumed it. Measured rather than assumed: a heartbeat showed one paint in eighteen seconds while minimized.
- [ ] **#119 Ward speaks in a premium voice too** — A second, paid voice provider alongside the free one, chosen per role, so a Commander with a key hears it and nothing else changes. Speed must be normalized across providers since they do not agree on the range they accept.
- [x] **#118 Ward's default text is too small to read at a glance** — On a 4K display the interface read as small. Measurement disproved the first diagnosis of a scaling defect — the 1.5 scale factor arrived and applied correctly — and the real cause was defaults chosen too small for the window.
- [ ] **#116 Let the journal propose a checklist item is done** — Where the journal can tell, Ward asks whether a checklist item is complete and marks it only after the Commander agrees. Never auto-marked, and silent where the journal cannot know, so it degrades to nothing rather than to a wrong answer.
- [ ] **#115 Know the current community goals** — Active community goals and their tiers. Surface the service's own rejection reason rather than guessing, and send an honest client identifier.
- [ ] **#114 Know about ships you are not flying** — Ship and module specifications from a dataset generated at build time and compiled in, so a rebuild is the refresh. Jump ranges are exactly where a model is most confidently wrong, so nothing is left to recollection.
- [ ] **#113 Find the closest one** — Nearest module, nearest ship for sale, stored ships and modules, plus body and signal lookups.
- [ ] **#112 Plan a route** — Neutron and long-range plotting, trade loops, Road to Riches, and mining routes.
- [ ] **#111 Search the galaxy** — Systems, stations and bodies, with real inter-system distances computed from coordinates. Query parameters are validated locally because the search service silently ignores filter keys it does not recognize, which would quietly widen a search.
- [ ] **#110 Fill the quiet with ambient chatter** — In-character ambient lines motivated by live game state, varied enough not to repeat noticeably.
- [ ] **#109 Speak incoming messages in another voice** — Re-voice in-game communications so they do not arrive in Ward's own voice. Every added voice goes through the same arbiter, since separate paths are how a broadcast ends up spoken as the companion.
- [ ] **#108 Give the carrier a Captain and Tower** — Dedicated voices for fleet carrier personnel, with arrival and departure responses and a configurable carrier name.
- [ ] **#107 Give the ship a crew** — Multi-character roleplay on the conversation path, with per-ship rosters drawn from the real fleet and hired NPC pilots imported from the journal with their roles.
- [ ] **#106 Remember things across sessions** — A Commander block in the system prompt holding only what the journal cannot derive: forms of address, tone preferences, standing goals. Ranks, ships and location stay out because they go stale inside a cached prefix.
- [ ] **#105 Cancel Ward's own voice out of the microphone** — Acoustic echo cancellation, the unlock for continuous listening and natural interruption. Without it, listening while Ward speaks just means transcribing Ward.
- [ ] **#104 Start a turn by saying its name** — Wake-word gating, implemented as another gate policy over the same audio stream.
- [ ] **#103 Listen without a key held** — Voice activity detection as a continuous-listening gate policy over the existing stream, making it an addition rather than a rewrite.
- [ ] **#102 Help with engineering** — Blueprints, material sourcing, per-ship engineering plans, and on-foot suit and weapon engineering. At least two epics' worth, deliberately left vague until it is next.
- [ ] **#101 Know the engineers** — Who unlocks what, current unlock status, where each engineer is, and what they grade.
- [ ] **#100 Let the Commander author macros** — Named multi-step voice-triggered sequences, validated against closed vocabularies and the action allowlist, with voice authoring and the settings form sharing one validator. The macro store takes a lock so a panel edit racing a voice edit cannot lose a create.
- [ ] **#99 Configure how surfaces follow you** — Head-locked or world-locked placement, and how each VR surface behaves when you turn your head.
- [ ] **#98 Configure the captions** — On/off, line count, text size and dwell time for the caption layer.
- [ ] **#97 Configure how the overlay looks** — Opacity, curvature, distance and size, configurable per surface.
- [ ] **#96 Give ambient audio a mixer** — Per-category levels and mute, plus how each category ducks against speech.
- [ ] **#95 Let the Commander supply their own cues and effects** — Drop in your own audio files and have Ward use them, kept distinct from the set Ward ships with.
- [ ] **#94 Play ambient music** — Music separate from cues and sound effects, with its own level and its own ducking behavior against speech.
- [ ] **#93 Offer a mode with no personality** — Plain answers with no persona, flavor or ambient remarks. The anti-invention guardrails must survive the persona being switched off, so they cannot live inside the persona's prompt block.
- [ ] **#92 Support more voice providers** — Additional providers beyond the two already chosen, only where one genuinely earns its place. Deliberately not a matrix, since each provider is support cost the maintainer personally pays.
- [ ] **#91 Set the speaking speed** — A speed setting normalized across providers, which do not agree on limits — one clamps to a narrow band, another goes well past it — so no provider's range can be hardcoded.
- [ ] **#90 Let the model search the web** — Live web search as a tool, crossing the line that otherwise keeps Ward network-free beyond the model. Usable only where results carry citations, and when search is unreachable Ward says so rather than answering from memory.
- [ ] **#89 Choose the transcription model** — Right-sizing the speech model is a free latency win, but the accuracy trade depends on hardware Ward cannot know about, so the Commander picks.
- [ ] **#88 Choose how hard the model thinks** — Per-turn thinking effort from low through max, the largest and least obvious latency lever since the first audio waits on thinking. "Off" is never offered, because disabling thinking can make the model write a tool call as visible text and claim an action it never took.
- [ ] **#87 Choose which model runs the turn** — Pick the model from a live catalog rather than a typed string. The tier axis matters more than the vendor axis here, since a voice turn is a cached prefix plus a few hundred output tokens.
- [ ] **#86 Say numbers and dates the local way** — Locale-aware formatting in spoken callouts so distances, times and quantities are said correctly instead of read out in one fixed convention.
- [ ] **#85 Speak in the Commander's language** — Locale-aware voice pairing, so localisation reaches the spoken voice rather than stopping at interface strings.
- [ ] **#84 Transcribe in the Commander's language** — Automatic language selection for speech recognition.
- [ ] **#83 Translate the interface** — Stable string identifiers rather than English source strings, since keying on English turns a copy-edit into silent data loss. A language ships only with a complete catalog; CI fails on missing or orphaned identifiers.
- [ ] **#82 Write down what happens if I stop** — Sustainability and bus-factor documentation. A public project with one maintainer owes readers an honest answer about continuity.
- [ ] **#81 Add the contributor and conduct files** — CONTRIBUTING, a code of conduct, and a disclaimer. NOTICE is handled separately, landing with the first dependency that needs it.
- [ ] **#80 Decide which tools ship on a turn as the count grows** — At some capability count the tool schemas stop fitting comfortably in context and something must choose between them. Whatever is chosen, the anti-invention guardrails are static prompt material and must never be strippable by a budget or effort setting.
- [ ] **#79 Account for what a turn cost** — Per-turn token usage including cache reads, priced from a table, plus a session summary at shutdown.
- [ ] **#78 Capture a keypress to bind a hotkey** — Press the key to bind it, instead of typing the key's name and hoping the spelling matches.
- [ ] **#77 Show the overlay even when SteamVR starts second** — Overlay creation is a one-shot attempt, so if the headset comes up after Ward the overlay never appears and nothing explains why.
- [ ] **#76 Offer one searchable picker everywhere a value is chosen** — A command-palette style picker with keyboard navigation, reused for voices, models and devices. Fail-soft by contract: with an empty list you can still keep the current value or type one.
- [ ] **#75 Copy the whole filtered log** — One affordance for grabbing an entire session's log as filtered, rather than hand-selecting it.
- [ ] **#74 Give the companion a face** — Per-state avatar imagery on the panel. Animated formats need frame decoding rather than a static image loader.
- [ ] **#73 Say when the persona has changed** — A persona switch with no audible acknowledgement leaves the Commander unsure whether it took effect.
- [ ] **#72 Let the Commander name their companion** — Choose what the companion is called, and have it answer to that name.
- [ ] **#71 Navigate the system map by voice** — The same keystroke-injection mechanism applied to bodies and stations within a system.
- [ ] **#70 Set a course by driving the galaxy map** — Plot a destination by sending keystrokes to the in-game galaxy map. This is the only course-setting route that needs no external service, so it works with nothing but Elite running.
- [ ] **#69 Report a joystick-only binding as unusable** — An action bound only to a HOTAS is marked unusable with a clear message rather than silently doing nothing. For this audience the honesty matters more than the feature.
- [ ] **#68 Send an in-game message by voice** — Dictate into Elite's chat: local, wing or system.
- [ ] **#67 Control on-foot actions by voice** — Tools, gear and weapon selection while on foot.
- [ ] **#66 Control the SRV by voice** — Driving controls, turret, dismiss and recall.
- [ ] **#65 Control panels, UI and fire groups by voice** — Cycle the panels and fire groups without taking a hand off the stick.
- [ ] **#64 Control ship systems by voice** — Power distribution, fuel scoop, silent running and heat sinks.
- [ ] **#63 Control flight and navigation by voice** — Landing gear, lights, cargo scoop, hardpoints and the frame shift drive.
- [ ] **#62 Offer only the actions that work right now** — Mode-gated action advertisement, so the set differs on foot, in the SRV and in the cockpit and the model is never told about a key that currently does nothing.
- [ ] **#61 Keep a checklist per ship** — Checklists that belong to a specific ship and follow it, instead of one global list.
- [ ] **#60 Warn about cargo before a ship swap strands it** — The journal reports a ship swap only after it happens, too late to help. Fire on the precursor instead — docking somewhere with a shipyard while carrying cargo.
- [ ] **#59 Remark on an unusually long jump** — Flavor during a longer-than-normal hyperspace jump, fired once hyperspace has actually been entered rather than on the jump being initiated.
- [ ] **#58 Recognize where you have arrived** — Place-aware callouts for engineer bases, notable stations, and somewhere you visit often.
- [ ] **#57 Remember how often you have been somewhere** — A visit ledger supporting remarks like "you have been here ten times today." Visit windows are computed in UTC, since journal timestamps are UTC and parsing them as local skews the 24-hour and 7-day windows.
- [ ] **#56 Answer questions about ship metrics** — Jump range and similar, computed from what the loadout event actually reports rather than from a table of ship specifications.
- [ ] **#55 Know what ships you own and where they are** — A fleet registry built from stored-ships journal events.
- [ ] **#54 Know what is in your backpack and ship locker** — On-foot inventory parsed from the local files Elite writes.
- [ ] **#53 Be aware on foot and in the SRV** — Mode-aware answers when you are not in the cockpit, driven by the status file's mode rather than inferred.
- [ ] **#52 Know your current ship's loadout** — Modules and stats from the loadout event, which carries maximum jump range directly and so answers jump range with no embedded dataset.
- [ ] **#51 Say so when the model is misconfigured** — An audible warning when the provider setup is wrong, rather than silence that is indistinguishable from a model with nothing to say.
- [ ] **#50 Let the router name its own doubt** — An explicit "unsure" result instead of a confidence threshold, because models produce confident-sounding scores that do not mean anything. A model-free keyword router ships alongside so the whole path is exercisable without a model.
- [ ] **#49 Treat capabilities as state, never as a guard** — A dead network flips a capability off and the next turn reads what is currently available, so there is no failure handler to author or keep in register. It falls out that every input path must be answerable with no capabilities at all.
- [ ] **#48 Link each settings row to its documentation** — A setup-guide link per settings row pointing at that setting's page. In-app help stays the short form; the page is the long form.
- [ ] **#47 Report diagnostics with spans and a help line** — Accumulating reports rendered compiler-style with the source line and carets, because nearly every check is a relationship between two places and pointing at one is half an answer.
- [ ] **#46 Capture a crash to a local file** — Opt-in, off by default, redacted and never transmitted. Installation is entirely fail-soft, since a crash reporter that raises during a crash is worse than none.
- [ ] **#45 Redact secrets and paths from everything written** — Strip encrypted key blobs, API tokens and the user profile path from diagnostics before they hit disk so the file is safe to hand to someone. Redaction and formatting are pure functions, testable without producing a crash.
- [ ] **#44 Turn a subsystem up without restarting** — Runtime per-subsystem verbosity control. It matters most in VR, where restarting means taking the headset off and "reproduce it with logging on" costs a second run.
- [ ] **#43 Collapse settings cards** — Collapsible sections whose collapse state is remembered as a view preference, not a setting, and applied before first paint so a collapsed card never flashes open.
- [ ] **#42 Protect safety-critical settings from the model** — Rows gating keyboard actions and macros are marked protected: changeable by hand or through the panel, never through a tool the model can call. The model consumes untrusted text, so a guard it can flip is privilege escalation.
- [ ] **#41 Show the controls the active provider actually has** — Settings adapt to the selected provider instead of showing a hardwired set, and changing an endpoint resets the model list to that endpoint's namespace rather than leaving a stale selection.
- [ ] **#40 Apply every setting without a restart** — Changing a setting takes effect immediately. A setting that silently resolves once at startup while appearing live is worse than one that plainly requires a restart.
- [ ] **#39 Follow the live log, or stop following it** — A floating jump-to-latest control with follow and scroll-lock, so reading history does not mean fighting new lines as they arrive.
- [ ] **#38 Make the live log selectable and copyable** — Read back what was said and copy it out. Free-form drag-selection across a continuously appending log is the hard part; rendering it as one read-only block is the way around it.
- [ ] **#37 Offer a theme** — Dark, light, and an Elite-flavored palette, with color living in one place so no view hardcodes a literal.
- [ ] **#36 Scale the big panel** — Zoom the panel up and down in the headset, distinct from mini mode, which reduces content rather than shrinking the rendering.
- [ ] **#35 Pick up dropped-in audio without a restart** — Cues, sound effects, music and ambient content discovered from convention folders and reloaded live.
- [ ] **#34 Write Ward's own lore** — Why it is called Ward, captured as a tracked artifact rather than folklore. Ward is a Guardian AI, a deliberate Elite Dangerous lore choice and the identity the product is built around.
- [ ] **#33 Pair a default voice to each persona** — A sensible voice chosen for each persona in the background, so picking a character does not also mean auditioning hundreds of voices.
- [ ] **#32 Ship more than one persona** — Pre-built companion characters the Commander can choose between.
- [ ] **#31 Put something on the clipboard** — A system name, route or value placed on the clipboard so it can be pasted into the game or a browser.
- [ ] **#30 Call out progress along a plotted route** — Jumps remaining, next system, neutron and white-dwarf hazards ahead, and scoopable-star ambiguity resolved rather than guessed. Reads the route file Elite writes locally, so no route-planning service is needed.
- [ ] **#29 Call out material-gathering milestones** — The first unit, then 25/50/75%, a running count above 75%, and full. The tracker is primed from the session backlog at startup, or starting Ward after Elite means the milestones never fire.
- [ ] **#28 Know what materials you are carrying** — Materials inventory built from journal events, answerable without an external lookup.
- [ ] **#27 Know your location and your carrier** — Current system, station and body, plus where your fleet carrier is.
- [ ] **#26 Know what is happening around you** — Live situational awareness attached to each turn: where you are, what you are flying, and what just happened.
- [ ] **#25 Answer what version you are running** — The running version, spoken aloud and visible in the panel.
- [ ] **#24 Answer what can you do, from the registry** — Spoken help projected from the capability registry — groups, then capabilities, then detail and example phrasings — ranked by real usage. The model is never asked what Ward can do, because asking produces confidently invented capabilities.
- [ ] **#23 Report a key that is bound twice** — A double-bound push-to-talk key currently has no symptom other than not working; detect the collision and say so.
- [ ] **#22 Say something when a turn is taking too long** — Retry with backoff, and after about thirty seconds say so aloud in the current voice rather than leaving silence.
- [ ] **#21 Choose the microphone in settings** — Pick the input device instead of inheriting the system default. A blank selection produces a silent default and a turn reporting no speech detected, with nothing indicating why.
- [ ] **#20 Give every loop state its own audio cue** — Several variants per state picked at random, so no pattern becomes audible over a long session. Cue names come from the shipped resources rather than a hand-written table, since a wrong name goes wrong as silence nobody notices.
- [ ] **#19 Play a listening cue when the key goes down** — A short cue at the start of capture so you know recording began, with tunable length — long enough to notice, short enough not to eat the first word.
- [ ] **#18 Play a thinking bed while the model works** — Audible evidence that Ward heard you and is working, instead of dead air while a turn runs.
- [ ] **#17 Bias transcription with proper nouns from the journal** — Feed system, station and ship names from the journal into the transcriber so they come back spelled correctly. Journal-derived and network-free; proper nouns are where speech recognition fails hardest and most silently.
- [x] **#16 Every capability has a documentation page** — CI fails if a registered capability has no documentation page, making "write the docs later" impossible rather than merely discouraged. Pages are written from real artifacts and must quote at least one code block or line of real output.
- [x] **#15 Ward installs on a clean machine** — Installability treated as a 0.1.0 feature rather than a packaging afterthought, so no source-mode path ever diverges from the installed one. Per-user install, no elevation, unsigned with a published checksum, and a single statically linked binary.
- [x] **#14 Ward is configured without manually editing a file** — Every setting, including the voice, is changeable in the UI with no hand-editing. Rows are generated from capability descriptors, defaults appear as placeholders rather than values, keys are write-only, and safety-critical rows are protected from the model.
- [x] **#13 Ward's panel works in VR** — One widget tree renders to both the desktop window and VR, so the windowed UI can never be more functional than the headset one. Mini is a mode of the same panel — a reduced content set — not a separate surface or a scaled-down copy.
- [x] **#12 Ward appears in the headset** — Captions render over Elite in VR through OpenVR (Elite never calls OpenXR) and clear on their own. Captions are their own unmovable, output-only, ephemeral layer with a rolling three-line window timed from the end of speech.
- [x] **#11 Ward keeps a checklist** — Add, complete and read checklist items by voice, with the panel reflecting changes live. The store takes a lock so a panel edit racing a voice edit cannot lose a create or resurrect a delete, and one display model projects the same answer across table, mini, spoken and caption densities.
- [x] **#10 Ward honks when you arrive** — The discovery scanner fires on entering a new system using the Commander's own key binding, injected via scancodes with the Elite window focused. Never installs a low-level keyboard hook, and `release_all()` is unconditional because a stranded key here is a throttle that will not stop.
- [x] **#9 Journal behavior is testable without the game** — A recorded session replays deterministically at 1x and 100x with no game, headset or hardware. Fixtures are byte-preserved via `.gitattributes` and scrubbed of the Commander name and real system visits, since the repository is public.
- [x] **#8 Ward knows where you are** — Ward answers what system you are in from the journal as part of an ordinary turn. Picks the newest journal by ordinal filename sort, opens shared for read/write/delete since Elite holds the file open, and is pull-based with no internal thread, which is what makes it testable.
- [x] **#7 Ward hears you hold a key** — Hold the key, speak, release, and your words appear. The key-down path awaits nothing before recording starts, and push-to-talk is one gate policy over an audio stream so continuous listening and wake word become later policies rather than a rewrite.
- [x] **#6 Ward speaks its answer aloud** — The reply is audible in the chosen voice, via the second of two hand-rolled protocols with no official Rust client. Synthesis is sentence-chunked so speaking starts at the first sentence boundary — the largest perceived-latency win available.
- [x] **#5 Ward speaks on one arbitrated stream** — Everything audible goes through one queue with priority and supersede, including audio cues, so ducking, interruption and captioning need no second mechanism. One arbiter for every voice, because separate paths per voice are how a line gets spoken in the wrong one.
- [x] **#4 Ward calls a capability** — A request produces a real tool call that runs and returns a result, covering the capability registry and the descriptor declaring identity, tools, help, settings rows and display model. Descriptors are registered once and never mutated so tool schemas stay byte-identical across turns for prompt caching.
- [x] **#3 Ward keeps your key and your state safe** — Settings survive a restart, unknown keys are rejected, and everything writable lives in one folder beside the executable. Two stores because one loader cannot both fail loudly and shrug; writes go to a `.writing` sibling then an atomic move, and secrets are DPAPI-encrypted at rest.
- [x] **#2 Ward says what went wrong** — Levels, one target per subsystem, structured fields, and two sinks — one human-readable, one machine-readable so an agent can parse a session. Nothing leaves the machine: no analytics, no metrics endpoint, no upload.
- [x] **#1 Ward answers a typed question** — Type a question into Ward's window and get a streamed reply from the model, covering the hand-rolled Anthropic client, a minimal egui window, and enough configuration to read an API key. Thinking stays on, because disabling it can make the model write a tool call as visible text and claim an action it never took.
